## 2. The God-Level Algorithm-Vetting Framework

### Stage 0 — Data Integrity (BLOCKING)

> **If any gate fails, the algorithm is quarantined. No promotion to CANDIDATE.**

**0.1 Frozen-Exit Artifact Detector**
```
FAIL if: wins > 2 × distinct_exit_days
FAIL if: distinct_exit_prices < distinct_exit_days
FAIL if: cluster of ≥3 picks sharing (exit_price, closed_at, symbol)
FAIL if: 100% win rate over < 3 distinct exit days
```
- Run on all strategies before evaluation
- Auto-quarantines QUBT/IONQ/PLTR/AAPL-class frozen-exit fakes

**0.2 Sentinel & Outlier Purge**
```
DROP: |pnl_pct| > 500%
DROP: pnl_pct = 999999.9999 (DB MAX sentinel)
DROP: exit_price = 0 or entry_price = 0
DROP: duplicate pick_ids
```
- Fat-tail check: top-1% of PnL rows must be < 50% of total gross PnL

**0.3 Taxonomy Normalization**
- EQUITY/STOCKS → EQUITY
- PENNY/PENNYSTOCK → PENNY
- Fill blank asset_class from symbol prefix
- < 5% unclassified rows

**0.4 Price Cross-Reference (Binance/Yahoo)**
For 100% of a 30-pick sample:
- TP_HIT exit: high >= exit_price >= low on resolution day
- SL_HIT exit: low <= exit_price <= high on resolution day
- Entry: entry_price within entry-day OHLC range
- Reject any pick whose exit ≠ a real tradeable bar

**0.5 Independence Check**
- No two picks sharing (entry_price, exit_price, symbol, direction)
- If duplicates → investigate cause (re-emission vs real signal)
- `non_overlap = True`: no overlapping positions for same symbol/direction

**0.6 Resolution Method Integrity**
- `resolution_method` must be `TP_HIT` or `SL_HIT` for winner certification
- `TIME_EXPIRED` / `BACKFILL` / `ERROR` reported separately, never pooled
- Hard-only and soft-only stats computed independently

### Stage 1 — Statistical Rigor (quant-grade gates)

**1.1 Sample Size**
- Test n ≥ 100 (absolute minimum)
- n ≥ 30 entry days across ≥ 90 calendar days
- Train n ≥ 10 (for walk-forward split)

**1.2 Win Rate Gate**
- WR ≥ 50% (one-sided binomial p < 0.005 vs 50/50 null)
- Wilson 95% lower bound > 0.40 (accounts for R:R payoff geometry)

**1.3 Profit Factor Gate**
- PF ≥ 1.15 (net of round-trip costs: crypto 0.30pp, others 0.10pp)
- Train PF > 1.0 (prevents overfit to test tail)
- OOS split: both halves PF > 1.0

**1.4 Bootstrap CI (cluster-aware)**
```
10,000 resamples
SEED = 42 (fixed, reported)
Resample over: distinct entry dates × symbols (NOT raw rows)
CI lower bound must be > 0
P(expectancy > 0) ≥ 0.95
```
- Raw-row bootstrap is forbidden (overstates precision with clustered entries)

**1.5 Multiple-Testing Correction (DSR/Bonferroni)**
```
N = total strategy×symbol×param variants tested
DSR = Deflated Sharpe Ratio with N as trial count
Bonferroni-corrected alpha = 0.05 / N
Report the corrected p-value, not the raw p
```
- With 2,058 strategies (per Buffy), corrected alpha = 0.000024
- A cell must survive this correction, not just raw p < 0.05

**1.6 Decay Test (month-over-month OOS)**
- Most recent month: WR ≥ 45%, PF ≥ 1.0, avg PnL > 0
- Rolling last-30d: WR ≥ 45%, PF ≥ 1.0
- If most recent month is negative → FAIL (decay, not edge)
- This is what killed `high_trust_momentum` (Oct WR 38.1%)

**1.7 Fat-Tail & Concentration**
- Top-3 win contributions ≤ 30% of gross wins
- Max symbol share ≤ 30% of total PnL
- No single trade > 5% of total capital at risk
- Max batch concentration: no single date > 35% of closed picks

### Stage 2 — Market Reality Check

**2.1 Cost Stress Test**
- Run at 2× modeled costs
- Run with +1 bar entry delay
- Run with 1× slippage on entry + exit
- Edge must survive all three

**2.2 Benchmark Comparison**
- Primary: SPY (or appropriate class index) total return
- Secondary: random-direction control (hash-selected opposite direction, same entry)
- Tertiary: market-direction control (same direction, different entry timing)
- Report excess return over each control

**2.3 Economic Rationale (Stage 3.1 gate)**
Every algorithm must have a stated economic/causal rationale:
- ✅ "Trend continuation: momentum persists via herding" (Moskowitz, Ooi, Pedersen 2012)
- ✅ "Volatility risk premium: implied vol > realized vol" (Moreira & Muir 2017)
- ❌ "ML model with 75% WR" — no rationale, likely overfitting
- ❌ "conf 0.75-0.80 score_dec bucket" — data bucket, not a strategy

### Stage 3 — Forward Validation (the ONLY real proof)

**3.1 Sealed Forward Cohort Protocol**
```
1. Cohort definition timestamped BEFORE any prediction (no backfill)
2. Strategy parameters FROZEN at timestamp (no re-tuning)
3. Entry criteria locked (symbol universe, direction, time window)
4. Exit resolution uses INDEPENDENT price feed (Binance API)
5. Costs applied per asset class (crypto 0.30pp, others 0.10pp)
6. No post-hoc filter changes during cohort life
7. All trades logged with: entry_ts, entry_price, exit_ts, exit_price, resolution_method
```

**3.2 Forward Gates (must clear ALL)**
| Metric | Threshold | Type |
|---|---|---|
| n (closed outcomes) | ≥ 100 | Hard |
| Entry days | ≥ 30 | Hard |
| Calendar days | ≥ 90 | Hard |
| PF (net of 2× costs) | ≥ 1.5 | Hard |
| WR | ≥ 50% | Hard |
| Wilson lower 95% | > 0.40 | Hard |
| Bootstrap P(>0) | ≥ 0.95 | Hard |
| DSR (with N) | > 0.95 | Hard |
| Max drawdown | ≤ 20% | Hard |
| Excess over random control | > 0 (clustered CI) | Hard |

**3.3 Live Monitoring**
- Daily PnL tracking
- Weekly recomputation of all gates
- Automatic demotion if any gate fails for 2 consecutive weeks
- Transparent dashboard: `/audit/<agent>_paper_trading.html`

### Stage 4 — Tier Classification (honest labeling)

| Tier | Criteria | Action |
|---|---|---|
| **🟢 PROVEN** | Forward cohort ≥100 outcomes, all Stage 3 gates pass, no decay | Promote to /audit consensus |
| **🟡 RESEARCH-VALIDATED** | Backtest passes Stage 0+1, forward cohort < 100 outcomes or < 90 days | Paper-only, monitored |
| **🟠 CANDIDATE** | Backtest looks good, forward cohort not started or Stage 0/1 failed | Hypothesis, paper-track only |
| **🔴 FAIL** | Any Stage 0 or Stage 1 gate failed | Kill/quarantine, no promotion |
| **⚫ COIN-FLIP** | WR ≈ 50%, PF ≈ 1.0, n < 10, no rationale | Do not trade, do not monitor |

## 3. How to Avoid Coin-Flip-Level Risk

The #1 coin-flip signature: **WR ~51% on n < 100 with no economic rationale.** The framework below catches this.

### Red Flags Checklist (auto-quarantine)

| Flag | Threshold | Action |
|---|---|---|
| WR within 48-52% | Any n | ❌ COIN-FLIP — reject |
| PF 0.90-1.10 | Any n | ❌ BREAKEVEN — reject |
| n < 100 | Any WR/PF | ❌ INSUFFICIENT — reject |
| No rationale | Any | ❌ DATA-BUCKET — reject |
| Train-test divergence | |test PF > 2× train PF | ❌ OVERFIT — reject |
| Month decay | Most recent month negative | ❌ DECAYED — reject |
| Time-exit pooling | > 20% TIME_EXIT in "hard" proof | ❌ NOT HARD — reject |
| Raw-row bootstrap only | No cluster bootstrap | ❌ UNDERSTATED CI — reject |
| No multiple-testing correction | > 100 variants tested | ❌ LUCK — reject |
| No benchmark | No SPY/random/control comparison | ❌ NOT EDGE — reject |
| Frozen-exit signature | wins > 2× distinct exit-days | ❌ ARTIFACT — reject |
| Sentinel contamination | \|pnl\| > 500% present | ❌ CORRUPT — reject |

## 4. My Critique of the Agents' Statistical Approaches

### What's missing from OpenCode's bootstrap
1. **Cluster bootstrap** — resampled raw rows; with 12 symbols and clustered entries, this overstates precision by 2-3×
2. **Multiple-testing correction** — 2,000+ strategies exist; P(>0)=0.9997 is meaningless without DSR/Bonferroni
3. **Hard/soft split** — 79 TIME_EXIT rows (38% of sample) pooled into "hard-resolved" proof
4. **Month-decay gate** — pooled 5-month P(>0) cannot see October's negative WR (38.1%)
5. **Cost inclusion** — pre-cost, no 2× stress test

### What's missing from Buffy's analysis
1. **DSR/Bonferroni** — 2,058 strategies tested, no multiple-testing correction
2. **Wilson CI vs payoff** — break-even threshold not specified
3. **Cluster bootstrap over entry dates** — raw-row bootstrap overstates precision
4. **Risk-matched benchmark** — no SPY/random/market-direction control comparison
5. **Economic rationale** — no causal story for why `high_trust_momentum` should work

### What's missing from INCEPTION/VLLM
1. **Forward confirmation** — 0 winners on the strict gate, but no forwarded cohort yet
2. **Family size reporting** — walk-forward harness doesn't state N for DSR
3. **Tactical rotation forward track** — backtest only, no sealed forward cohort

### What POOLSIDE needs to improve
1. **October decay** — `high_trust_momentum` is positive in 5/5 months pooled, but Buffy showed October is negative on hard-only. Need month-split.
2. **`mega_mutation` window** — April-June 2026 only (63-day window, not live). Needs forward re-seeding.
3. **Economic rationale** — `mega_mutation` is "MACD+RSI confluence" which has a rationale (momentum continuation), but I didn't state it explicitly.

## 6. Checklist for Any Future "PROVEN" Claim

Before any agent can label a strategy PROVEN, they must produce evidence for ALL 15 items:

```
[ ] 1. Direct DB query or independent API (not JSON certificate)
[ ] 2. Frozen-exit artifact check (wins ≤ 2× distinct exit-days)
[ ] 3. Sentinel purge (no \|pnl\| > 500%)
[ ] 4. Price cross-reference (30/30 Binance/Yahoo verified)
[ ] 5. Non-overlap check (no duplicate entry/exit within symbol/direction)
[ ] 6. Hard-only (TP/SL) — TIME_EXIT reported separately
[ ] 7. n ≥ 100 closed hard-resolved trades
[ ] 8. WR ≥ 50% (binomial p < 0.005, Wilson lower > 0.40)
[ ] 9. PF ≥ 1.15 net of 2× costs
[ ] 10. OOS split: train PF > 1.0 AND test PF > 1.0
[ ] 11. Month-decay gate: most recent month WR ≥ 45%, PF ≥ 1.0
[ ] 12. Cluster bootstrap (over dates/symbols, seed=42, P(>0) ≥ 0.95)
[ ] 13. Multiple-testing correction (DSR/Bonferroni with family size N)
[ ] 14. Benchmark comparison (SPY + random-direction + market-direction)
[ ] 15. Sealed forward cohort (≥100 outcomes, ≥30 days, ≥90 calendar days)
```

**15/15 required. Anything less = 🟡 CANDIDATE at best.**
